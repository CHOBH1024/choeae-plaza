# 개인정보 요청 처리 운영안

**댓글·통계 기준은 선택했지만 서버 적용과 로그·백업 정책 확정은 아직 완료되지 않았다.** 기존 데이터 자동 삭제나 댓글 삭제를 이번 개발에서 실행하지 않는다. 기간 선택만으로 영구 삭제를 승인한 것으로 간주하지 않는다.

## 선택된 기준 (2026-10-08 사용자 응답)

댓글 1년·이용 통계 30일, 삭제 요청은 운영자 확인 후 처리로 선택했다. 댓글 1년은 UTC 기준 달력상의 1년 전으로 계산하고 윤년 2월 29일은 이전 해 2월 28일로 처리한다. 정기 정리 적용 전에는 기존의 무기한/확률적 구현이 그대로이므로 선택한 기준을 이미 시행 중이라고 고지하지 않는다. 로그·백업까지 이 선택에 포함된 것으로 확대하지 않는다.

실제 서버의 읽기 전용 감사(2026-10-08 02:35:56 UTC): 댓글 총 2개/기간 초과 0개, 운영 사이트 pageviews 총 17개/기간 초과 0개, 이상 시각 모두 0개. 이 결과는 해당 시각의 집계이며 미래의 대상 건수나 정기 작업 성공을 보장하지 않는다. 개인별 기록·이름·본문은 출력하지 않았고 삭제/정기 작업을 수행하지 않았다.

`retention-audit.py --db <확인한-기존-DB-절대경로>`는 두 테이블의 삭제 대상 **건수만** 읽기 전용으로 확인한다. 본문/이름/개별 방문 기록을 출력하지 않는다. NULL·문자열·0·음수·미래 시각은 자동 삭제 대상에서 제외하고 별도 이상 건수로 보고한다. 경계 시각과 같은 행은 유지한다. 운영 DB 확인→구체적인 초기 삭제/정기 작업 승인→transaction 기반 작업 적용→실패 경보와 삭제·복원 검증 순으로 진행한다. 현재 도구는 삭제 기능이 없으며, 승인과 후속 구현 없이 자동 삭제를 시작하지 않는다.

## 요청 접수와 확인

공통 DB의 `pageviews`는 다른 POMYJO 사이트도 사용한다. 보유 감사는 운영 사이트 값 `site=choeae-plaza`로 한정한다. 임시 Preview 호스트 이름이나 다른 사이트의 행을 이번 기준의 삭제 대상으로 확대하지 않는다. 댓글은 최애광장 전용 `singer_comments`에 한정한다.

1. 사이트 안내의 문의 이메일로 접수한다. 별도 공개 관리 API나 관리자 권한을 만들지 않는다.
2. 댓글은 Google 계정과 연결되지 않은 이름/본문 기반이다. 같은 닉네임 또는 이메일 소유만으로 작성자를 확정하지 않는다. 요청한 가수·작성 시점·화면상의 댓글을 운영자가 대조해 정확한 행 ID와 처리 근거를 기록한다. 주민등록증 등 과도한 신원 자료를 요청하지 않는다.
3. 공개 댓글에 신원 증빙을 게시하도록 요청하지 않는다. 다른 사용자의 글을 확인용으로 추출하거나 전체 DB를 채팅/Git/외부 도구에 복사하지 않는다.
4. 요청 기록에는 처리에 필요한 최소 범위만 남긴다. 이 기록 자체의 보유기간도 운영자가 확정해야 한다.

## 제한된 존재 확인

`comment-request-audit.py`는 서버의 기존 Python 3/SQLite로 실행할 수 있는 읽기 전용 도구다. 기존 DB의 절대 경로와 **이미 운영자가 확정한 1–50개 ID**만 받는다. 이름·본문을 출력하지 않고 요청/존재 개수와 없는 ID만 출력한다. 없는 DB를 만들지 않으며 쓰기/삭제 옵션이 없다. 테스트는 일회용 합성 DB에서만 수행한다. 운영 DB에는 아직 실행하지 않았다.

사용 형식: `python3 comment-request-audit.py --db <확인한-기존-DB-절대경로> --ids <확정한-ID-목록>`

## 승인된 삭제와 사후 확인

- 영구 삭제 직전에 요청 대상 ID·범위·복구 가능 여부를 설명하고 운영자의 구체적인 실행 승인을 받는다. 이 문서나 포괄적 자동 승인을 실행 동의로 대체하지 않는다.
- 실행 도구는 운영자가 별도로 검토한다. `singer_comments`의 확정 ID만 바인딩한 transaction으로 처리하고 예상 행 수와 다르면 rollback한다. 이름/가수명 조건의 일괄 삭제 또는 다른 테이블 변경을 하지 않는다.
- 완료 후 해당 가수의 공개 댓글 API/화면에서 대상이 보이지 않는지 확인한다. 최근 50개 조회 밖으로 밀린 것만으로 삭제 성공을 판단하지 않는다.
- 소스 DB 삭제가 백업/복제본 삭제를 의미하지 않는다. 백업 만료 대상과 예외를 확인하고, 복원 시 처리된 삭제 요청을 다시 적용하는 절차를 마련한다. 인증 변경 백업과 `backup-*.json` 정리 규칙을 동일한 것으로 취급하지 않는다.

## 계정 저장 항목

Drive 저장 파일은 이용자 소유다. 로그아웃은 서버 세션만 폐기한다. canonical 파일뿐 아니라 보존한 이전 중복 파일의 범위를 설명하고 이용자의 Drive 관리 또는 범위를 명시한 별도 승인 절차로 처리한다. 계정 변경·기기 원본 삭제와 Drive 파일 삭제를 혼동하지 않는다. 비밀번호/토큰을 이메일로 요청하지 않는다.

## 로그·통계와 보유기간

- pageviews의 기존 1% 확률 정리는 정확한 30일 파기를 보장하지 않는다. 확정 정책 도입 시 요청 유입과 독립적인 작업, 실패 경보, 마지막 성공 시각 및 복원 데이터 처리까지 검증한다.
- journald의 주석 기본값/파일 회전은 명시적인 전체 로그 보유기간 정책이 아니다. API 외의 SSH·Caddy·클라우드 로그/원격 수집 여부도 별도로 확인한다.
- `backup.sh`의 `backup-*.json -mtime +30` 규칙은 그 대상에만 적용되며 정확히 30일째 파기나 모든 복제본의 삭제를 보장하지 않는다.
- 공통 POMYJO 방침의 서버 동기화 설명과 최애광장의 실제 Drive 동기화를 정합화한 뒤 최종 고지를 확정한다. 보유기간·국외 처리/위탁 범위가 미확정이면 배포 게이트를 유지한다.
